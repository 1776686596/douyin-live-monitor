# 抖音酒类直播间监控项目设计说明（初版）

> 本文档主要为了：  
> 1. 帮助自己理清项目架构  
> 2. 方便在面试中向面试官清晰介绍项目设计思路

## 一、项目目标

1. 不登陆抖音账号的前提下，监控多个酒类品牌直播间的数据：  
   - 实时在线人数  
   - 点赞数  
2. 对中国劲酒官方直播间，额外采集弹幕数据：  
   - 弹幕发送人昵称  
   - 弹幕内容  
3. 所有数据实时写入 MySQL 数据库（两个核心表：直播间指标表 + 弹幕表）  
4. 提供后端接口给前端使用，用于展示各直播间人气排名和劲酒弹幕列表  
5. 项目可迁移到云服务器部署，用于实际运行或者当成作品展示

## 二、整体架构设计

- 后端：Python + FastAPI  
- 爬虫：Playwright（或 Selenium）模拟浏览器，解析页面 DOM  
- 数据库：MySQL，SQLAlchemy 作为 ORM  
- 前端：React（后续搭建），通过 REST API 获取数据  

整体分层：

1. 接口层（FastAPI）  
   - 提供健康检查、直播间概览、弹幕查询等接口  
2. 业务逻辑层  
   - 调用 CRUD 封装进行数据查询和组装  
3. 持久化层（SQLAlchemy）  
   - 管理 MySQL 连接、模型定义和数据读写  
4. 爬虫层（crawler）  
   - 与抖音直播间页面交互，抓取实时数据

## 三、目录结构说明

当前项目目录（简化说明）：

- `backend/`：后端 + 爬虫代码  
  - `requirements.txt`：后端依赖列表  
  - `app/`：FastAPI 应用  
    - `main.py`：应用入口  
    - `config.py`：配置管理（MySQL 地址、爬虫间隔等）  
    - `database.py`：数据库连接、Session 管理、建表逻辑  
    - `models.py`：SQLAlchemy 数据表模型  
    - `schemas.py`：Pydantic 模型（API 输入/输出）  
    - `crud.py`：数据库 CRUD 封装  
    - `crawler/`：爬虫相关  
      - `douyin_client.py`：抖音直播间浏览器操作封装（待实现）  
      - `tasks.py`：后台任务调度（目前用模拟数据验证链路）  
- `frontend/`：前端占位目录（后续用 Vite + React 初始化）  
- `docs/`：文档  
  - `design.md`：架构与设计说明  

## 四、数据库设计

### 1. 直播间指标表 `live_room_metric`

用途：记录每个时间点的直播间快照，用于统计和趋势分析。

核心字段：

- `id`：主键  
- `room_name`：直播间名称（如“中国劲酒”“茅台”）  
- `room_url`：直播间链接  
- `online_count`：在线人数  
- `like_count`：点赞数  
- `is_live`：是否正在开播（若检测到未开播，写入 False）  
- `created_at`：记录创建时间（爬取时间点）

设计思路：  
- 不做“覆盖更新”，而是每次爬取都插一条记录，这样方便之后做趋势分析（例如画折线图）。  

### 2. 弹幕表 `danmu_message`

用途：记录中国劲酒直播间的弹幕数据。

核心字段：

- `id`：主键  
- `room_name`：直播间名称（冗余字段，方便按房间直接查询）  
- `sender_nickname`：发送人昵称  
- `content`：弹幕内容  
- `metric_id`：可选，关联到某次直播间指标记录  
- `created_at`：记录创建时间（爬取时间点）

设计思路：  
- 弹幕量可能比较大，可以根据需要设置定期归档或清理策略。  
- 通过 `metric_id` 可以把弹幕与当时的人气数据挂钩，方便做更细的分析。

## 五、爬虫设计思路（概念版）

> 目前代码里先用“模拟数据”写数据库，等整体链路稳定后再逐步替换为真实爬虫逻辑。

1. 使用 Playwright 启动无头浏览器  
2. 进入直播间页面 URL  
3. 根据你在 `request.md` 中给出的 DOM 路径/XPath：  
   - 解析点赞数元素：`<div class="kFUbYV4V">966本场点赞</div>`  
   - 解析在线人数元素：`<div class="ClV317pr" data-e2e="live-room-audience">26</div>`  
4. 对中国劲酒直播间：  
   - 持续监听弹幕列表 DOM 变化  
   - 抽取发送人和弹幕内容，例如：  
     - 发送人：`<span class="v8LY0gZF">小*****：</span>`  
     - 内容：`<span class="webcast-chatroom___content-with-emoji-text">1号是送杯子吗</span>`  
5. 每隔固定时间（例如 10 秒）执行一次爬取，将结果写入数据库。

## 六、接口设计（当前版本）

1. `GET /health`  
   - 功能：健康检查  
   - 返回：`{"status": "ok"}`  

2. `GET /overview/live-rooms`  
   - 功能：获取各直播间的最新概览信息，用于前端展示排名  
   - 逻辑：  
     - 每个直播间取最新一条直播间指标记录  
     - 统计最近 10 分钟内的弹幕数量（仅对有弹幕的房间有效）  

3. `GET /danmu/jingjiu?limit=50`  
   - 功能：获取中国劲酒直播间最近的若干条弹幕  
   - 参数：`limit` 控制返回条数  

## 七、后续可以优化/扩展的方向

1. 爬虫稳定性  
   - 处理抖音可能的反爬机制（例如滑块验证、频率限制）  
   - 增加异常重试和错误日志  
2. 性能与数据量控制  
   - 对历史数据做归档（例如只保留最近 N 天）  
   - 考虑增加 Redis 做热点数据缓存（例如首页展示）  
3. 前端体验  
   - 实时刷新动画、图表展示（折线图、柱状图）  
4. 部署  
   - 使用 Docker 容器化部署（后端 + 前端 + MySQL）  
   - 在云服务器上配置守护进程或系统服务，保证爬虫长期运行
